# Domain docs

## Before exploring

- Read root `GLOSSARY.md` when it exists.
- Read relevant architectural decisions under `docs/adr/`.

If these files are absent, proceed silently. Domain modeling creates
them when terms or decisions are resolved.

## Layout

This repo uses a single-context layout:

- `GLOSSARY.md`: shared domain vocabulary.
- `docs/adr/`: architectural decision records.

## Vocabulary and decisions

Use glossary terms in issue titles, proposals, hypotheses, and tests.
Reconsider unfamiliar terminology or note a gap for domain modeling.

If a proposal conflicts with an existing ADR, identify the ADR and
explain why the decision should be reconsidered.
